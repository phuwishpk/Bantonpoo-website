# คู่มือขึ้นเซิร์ฟเวอร์ — HostAtom Plesk (แบบแชร์)

โดเมน `bantonpoo.phuwish.com` · แผงควบคุม `https://103.80.48.25:8443` · ผู้ใช้ `phuwishs`

**ข้อจำกัดของโฮสต์นี้** — เป็นโฮสต์แบบแชร์ **ไม่มี SSH** (Plesk ล็อกไว้ที่ "Forbidden")
และให้ฐานข้อมูลมาแค่ MariaDB ซึ่ง Payload ใช้ไม่ได้ คู่มือนี้จึงใช้ **SQLite + FTP** ทั้งหมด
คำสั่งทุกบรรทัดพิมพ์ที่เครื่องของคุณเอง ในโฟลเดอร์โปรเจกต์

## 0. ภาพรวม

```
เครื่องคุณ                                        เซิร์ฟเวอร์ (บ้านของ phuwishs)
─────────                                        ──────────────────────────────
npm run deploy                                   bantonpoo.phuwish.com/       ← แอป (ถูกแทนที่ทุกครั้ง)
  ├─ ดาวน์โหลดฐานข้อมูลจริงลงมาอ่าน  ◄── FTP ──  bantonpoo.phuwish.com.prev/  ← เวอร์ชันก่อนหน้า
  ├─ build (Mac) + เติมไฟล์ native ของ Linux      bantonpoo-data/
  └─ อัปโหลดแล้วสลับเวอร์ชัน          ── FTP ──►   ├─ bantonpoo.db             ← เนื้อหาทั้งหมด
                                                    ├─ uploads/                 ← รูปที่อัปโหลด
                                                    ├─ app.env                  ← ค่าตั้งของแอป (มีกุญแจลับ)
                                                    └─ logs/app.log             ← log ของแอป
```

| เรื่อง            | ทำอย่างไร                                                                    |
| ----------------- | ---------------------------------------------------------------------------- |
| ฐานข้อมูล         | **SQLite** ไฟล์เดียว อยู่นอกโฟลเดอร์แอป จึงไม่หายตอน deploy                  |
| ส่งไฟล์           | **FTP แบบเข้ารหัส (FTPS)** ราว 2,400 ไฟล์ต่อครั้ง ส่งพร้อมกัน 4 การเชื่อมต่อ |
| ปรับโครงฐานข้อมูล | **แอปทำเองตอนเริ่มทำงาน** ไม่ต้องรันคำสั่งบนเซิร์ฟเวอร์                      |
| ค่าตั้งของแอป     | ไฟล์ `bantonpoo-data/app.env` — **สคริปต์สร้างให้เอง** (หัวข้อ 3)            |
| รีสตาร์ต          | วางไฟล์ `tmp/restart.txt` ให้ Passenger รีสตาร์ตเอง                          |
| ย้อนกลับ          | `npm run deploy:rollback` สลับกับเวอร์ชันก่อนหน้าได้ทันที                    |

**ฐานข้อมูลจริงไม่เคยถูกเขียนทับจากเครื่องคุณ** — ตอน deploy สคริปต์แค่คัดลอกลงมาอ่าน
ยกเว้น `deploy:init` ครั้งแรก ซึ่งจะตรวจก่อนเสมอว่าบนเซิร์ฟเวอร์ยังไม่มีไฟล์

### ทำไมบิลด์ต้องเติมไฟล์ของ Linux

บิลด์ที่ทำบน Mac ได้ไฟล์ native ของ macOS มาเท่านั้น (SQLite และตัวย่อรูป `sharp`)
แต่เซิร์ฟเวอร์เป็น Linux (Debian 12) ถ้าไม่เติม แอปจะโหลดไม่ขึ้นตั้งแต่บรรทัดแรก
สคริปต์จึงดาวน์โหลดไฟล์ของ Linux ทั้ง x64 และ arm64 มาใส่แทน (เก็บไว้ใน `.deploy-cache/`)
ใส่ทั้งสองสถาปัตยกรรมเพราะดูจากภายนอกไม่ได้ว่าโฮสต์เป็นแบบไหน

## 1. ตั้งรหัสผ่าน FTP

**Websites & Domains → bantonpoo.phuwish.com → Hosting & DNS → Hosting**
→ ลิงก์ **System user's credentials** ทางขวา

1. ช่อง **Password** → กด **Generate** → กดรูปตาเพื่อดูแล้ว **คัดลอกเก็บไว้**
2. กด **Save**

> รหัสผ่านนี้เป็นของ FTP คนละตัวกับรหัสผ่านเข้า Plesk — เปลี่ยนแล้วไม่กระทบการล็อกอินแผงควบคุม
> ค่านี้มีผลกับ **ทั้ง 3 โดเมน** ใน subscription เดียวกัน (Plesk ขึ้นป้าย "FOR 3 DOMAINS")
> ถ้ามีโปรแกรม FTP อื่นใช้รหัสเดิมอยู่ ต้องไปแก้ที่นั่นด้วย

## 3. ตั้งค่าในหน้า Node.js

**Websites & Domains → bantonpoo.phuwish.com → Node.js**

| ช่อง                     | ตั้งเป็น                                              |
| ------------------------ | ----------------------------------------------------- |

| Application Mode         | `production` (ไม่ต้องแก้)                             |

| Application Startup File | **`server.js`**                                       |

### ค่าตั้งของแอป — ไม่ต้องใส่ใน Plesk

**โฮสต์นี้ไม่ส่ง Custom environment variables ในหน้า Node.js มาถึงแอป** — ทดสอบแล้ว
ใส่ครบทุกช่องแอปก็ยังเห็นเป็นค่าว่าง (อาการเดียวกับที่มีรายงานใน
[Plesk Forum](https://talk.plesk.com/threads/node-environment-variables-not-returned-by-process-env.362424/))
แอปจึงอ่านค่าจากไฟล์ `bantonpoo-data/app.env` แทน ซึ่ง **`npm run deploy` สร้างให้เอง** ครั้งแรก

```
DATABASE_URI=file:../bantonpoo-data/bantonpoo.db
UPLOAD_DIR=../bantonpoo-data/uploads
PAYLOAD_SECRET=<สคริปต์สุ่มให้ 64 ตัวอักษร>
NEXT_PUBLIC_SITE_URL=https://bantonpoo.phuwish.com   ← สคริปต์ปรับให้ตรง DEPLOY_SITE_URL ทุกครั้ง
SITE_NOINDEX=1                                       ← สคริปต์ปรับให้ตรง DEPLOY_NOINDEX ทุกครั้ง
```

- **ไฟล์อยู่นอกโฟลเดอร์เว็บ** เปิดจากอินเทอร์เน็ตไม่ได้ และสคริปต์ตั้งสิทธิ์เป็น 600 (เจ้าของอ่านได้คนเดียว)
- **`PAYLOAD_SECRET` สุ่มครั้งเดียวแล้วไม่เปลี่ยนอีก** — deploy ครั้งต่อไปไม่แตะ
  ถ้าเปลี่ยนเองทุกคนจะหลุดจากระบบ ห้ามส่งไฟล์นี้ให้ใคร
- **แก้เองได้** ใน File Manager ของ Plesk แล้วกด **Restart App**
- **เส้นทางสัมพัทธ์ใช้ได้** เพราะ `server.js` ย้ายไปทำงานในโฟลเดอร์แอปของตัวเองเสมอ
  `../bantonpoo-data` จึงชี้ไปโฟลเดอร์ข้าง ๆ แอปพอดี
- **ค่าในไฟล์ชนะค่าใน Plesk** — ถ้าวันหนึ่งโฮสต์เริ่มส่งค่าเก่าจาก Plesk มา แอปจะไม่สลับไปใช้
  ฐานข้อมูลหรือกุญแจอื่นเงียบ ๆ ช่อง Custom environment variables ใน Plesk จึงลบทิ้งได้
- ไม่ต้องตั้ง `HOSTNAME` — Passenger เป็นคนรับการเชื่อมต่อแทนแอป

## 4. ติดตั้งครั้งแรก

```bash
npm run deploy:init
```

ใช้เวลาราว 5–10 นาที สคริปต์จะ:

1. ตรวจโค้ด
2. สร้างเนื้อหาตั้งต้นในเครื่อง แล้วอัปโหลดฐานข้อมูลและรูปขึ้น `bantonpoo-data/`
3. build + เติมไฟล์ native ของ Linux
4. อัปโหลดแอป แล้วสลับกับหน้า "Domain Default page" เดิมของ Plesk
5. รีสตาร์ตแอปและตรวจว่าเว็บตอบ 200

แล้วทำต่ออีกสองอย่าง

**สร้างบัญชีผู้ดูแลคนแรก** — เปิด `https://bantonpoo.phuwish.com/admin`
จะเจอจอ "สร้างผู้ใช้คนแรก" กรอกอีเมลและรหัสผ่าน บัญชีนี้ได้สิทธิ์ `admin` ทันที
จอนี้หายไปเองเมื่อมีผู้ใช้แล้ว คนต่อไปต้องให้ผู้ดูแลเชิญเข้ามา

**ตั้ง Document Root** — กลับไปหน้า Node.js แก้ **Document Root** เป็น
`/bantonpoo.phuwish.com/public` แล้วกด OK

> **ทำไมต้องแก้** — ถ้า Document Root ชี้โฟลเดอร์แอป ใครก็ดาวน์โหลด `server.js`
> และโค้ดฝั่งเซิร์ฟเวอร์ได้ตรง ๆ จากเว็บ (ไม่มีรหัสผ่านอยู่ในนั้น แต่ไม่ควรเปิดให้ดู)
> ต้องแก้หลัง deploy ครั้งแรก เพราะ Plesk ต้องเห็นโฟลเดอร์ `public/` ก่อนจึงจะยอมบันทึก
> สคริปต์ deploy ตรวจเรื่องนี้ให้ทุกครั้งและจะเตือนถ้ายังเปิดอยู่

ถ้าแก้แล้วหน้าเว็บพัง (ไม่มี CSS หรือ 404 ทั้งเว็บ) ให้ย้อนกลับเป็น `/bantonpoo.phuwish.com`
แล้วบอกผู้พัฒนา

## 5. อัปเดตเว็บครั้งต่อ ๆ ไป

```bash
npm run deploy
```

ใช้ **เนื้อหาจริงบนเซิร์ฟเวอร์** ตอน build (ดาวน์โหลดลงมาอ่านอย่างเดียว) จึงไม่มีทาง
เอาเนื้อหาของเครื่องพัฒนาขึ้นไปทับ

**ทำไม build ต้องอ่านเนื้อหาจริง** — หน้าแรก หน้าสินค้า และหน้าบทความถูกสร้างเป็นไฟล์
ล่วงหน้าตอน build ถ้าอ่านจากฐานข้อมูลอื่น เว็บจะแสดงเนื้อหาชุดนั้นจนกว่าจะมีคนแก้หน้านั้น

## 6. ย้อนกลับ

```bash
npm run deploy:rollback
```

สลับเวอร์ชันที่ใช้อยู่กับเวอร์ชันก่อนหน้า (รันซ้ำเพื่อสลับกลับ) — **ไม่แตะฐานข้อมูล**
ถ้าเวอร์ชันใหม่ปรับโครงฐานข้อมูลไปแล้ว การย้อนแอปอาจไม่พอ ต้องกู้ไฟล์สำรองด้วย (หัวข้อ 9)

## 7. ตรวจหลัง deploy

```bash
curl -I https://bantonpoo.phuwish.com                     # 200
curl -s https://bantonpoo.phuwish.com/robots.txt          # Disallow: / ตอนเป็นโดเมนทดสอบ
CHECK_BASE_URL=https://bantonpoo.phuwish.com npm run check:public
```

`check:public` ตรวจว่าไม่มีลิงก์หลังบ้านหรือที่อยู่ฟิลด์หลุดไปถึงผู้เข้าชมทั่วไป

### ดู log เมื่อมีปัญหา

log ของ Passenger อยู่ในที่ที่ผู้ใช้โฮสต์แชร์เปิดไม่ได้ แอปจึงเขียนสำเนาไว้เองที่
**`bantonpoo-data/logs/app.log`** (เปิดใน File Manager ของ Plesk) — ไฟล์เกิน 5 MB
จะถูกย้ายเป็น `app.log.1`

ทุกครั้งที่แอปเริ่มทำงานจะเขียนบรรทัด `startup:` บอกรุ่น Node, ไฟล์ค่าตั้งที่อ่านได้,
ค่าที่ตั้งแล้ว/ยังไม่ตั้ง (กุญแจลับบอกแค่ว่ามี), สิทธิ์ของฐานข้อมูลและโฟลเดอร์รูป
และผลการโหลด SQLite กับ sharp ส่วน error ระหว่างเปิดหน้าเว็บขึ้นเป็น `request-error:` พร้อมชื่อหน้า

**Websites & Domains → bantonpoo.phuwish.com → Logs** มีแค่ log ของ Apache/nginx
ไม่มีข้อความจากแอป

## 8. การเปลี่ยนโครงฐานข้อมูล (migration)

ทุกครั้งที่ **เพิ่ม ลบ หรือเปลี่ยนชนิดฟิลด์** ใน `src/collections/*` หรือ `src/globals/*`

| สภาพแวดล้อม  | วิธีปรับโครง                                       |
| ------------ | -------------------------------------------------- |
| เครื่องพัฒนา | Payload ปรับให้อัตโนมัติตอน `npm run dev` (`push`) |
| เซิร์ฟเวอร์  | แอปรันไฟล์ migration ที่ยังค้างเองตอนเริ่มทำงาน    |

**ขั้นตอนหลังแก้ฟิลด์**

```bash
# 1. สร้างไฟล์ migration โดยเทียบกับฐานข้อมูลที่เป็นโครงเดิม
#    (ย้อนโค้ดกลับไปก่อนแก้ แล้วรัน migrate ใส่ไฟล์เปล่า หรือใช้สำเนาฐานข้อมูลจริง)
DATABASE_URI=file:/tmp/diff.db NODE_ENV=production npm run migrate:create ชื่อสั้น

# 2. อ่านไฟล์ที่ได้ใน src/migrations/ ก่อนเสมอ
#    ระวัง DROP TABLE — SQLite เปลี่ยนชนิดคอลัมน์ไม่ได้ Payload จึงอาจสร้างตารางใหม่
#    แล้วคัดลอกข้อมูล ตรวจว่าคัดลอกครบทุกคอลัมน์
#    ถ้าเป็นการ "เปลี่ยนชื่อฟิลด์" ต้องแก้เป็น ALTER TABLE ... RENAME COLUMN เอง

# 3. commit แล้ว deploy ตามปกติ — build จะรัน migration กับสำเนาฐานข้อมูลจริงก่อน
#    ถ้าพังจะพังที่เครื่องคุณ ไม่ใช่บนเว็บจริง
git add src/migrations && git commit
npm run deploy
```

**แอปปรับโครงอย่างไรไม่ให้ชนกัน** — ทั้ง `next build` (หลาย worker) และ Passenger
(หลายโพรเซส) เปิดแอปพร้อมกันได้ ถ้าต่างคนต่างรัน migration จะชนกันด้วย
"table already exists" (เจอจริงตอนทดสอบ) จึงล็อกด้วยโฟลเดอร์ `bantonpoo.db.migrate-lock`
ให้ทำทีละโพรเซส ดูรายละเอียดที่ `src/lib/cms/migrate-on-start.ts`

> **อย่าอัปโหลดไฟล์ฐานข้อมูลของเครื่องพัฒนาขึ้นเซิร์ฟเวอร์** — ไฟล์นั้นผ่านโหมด `push` มาแล้ว
> Payload จะหยุดถามยืนยันในเทอร์มินัลซึ่งบนเซิร์ฟเวอร์ไม่มีใครตอบ แอปจึงข้ามการปรับโครง
> และเขียน log เตือนไว้แทน

## 9. สำรองข้อมูล

ทั้งเว็บอยู่ในโฟลเดอร์ `bantonpoo-data/` เดียว (ฐานข้อมูล + รูปที่อัปโหลด)
ซึ่งอยู่ในบ้านของ subscription **Plesk Backup Manager จึงสำรองให้ครบ**

ตั้งที่ **Websites & Domains → Backup Manager** ให้สำรองรายวัน และส่งออกไปเก็บนอกเครื่อง
อย่างน้อยสัปดาห์ละครั้ง — เก็บบนเครื่องเดียวกันอย่างเดียวไม่พอ

ไฟล์สำรองมี `app.env` ซึ่งมีกุญแจลับอยู่ด้วย — เก็บไฟล์สำรองไว้ในที่ที่คนอื่นเปิดไม่ได้

ดึงสำเนาฐานข้อมูลลงมาเองก่อนทำอะไรเสี่ยง: ใช้ **File Manager** ของ Plesk
เข้าโฟลเดอร์ `bantonpoo-data` แล้วดาวน์โหลด `bantonpoo.db`

**กู้คืน** — หน้า Node.js กด **Disable Node.js** → อัปโหลดไฟล์สำรองทับ `bantonpoo.db`
ผ่าน File Manager → กด **Enable Node.js** (ต้องปิดแอปก่อน ไม่งั้นไฟล์อาจเสียหาย)

## 10. เมื่อจะเปลี่ยนเป็นเว็บจริง

1. ใน `.env.deploy.local` ตั้ง `DEPLOY_NOINDEX=0` และ `DEPLOY_SITE_URL` เป็นโดเมนจริง
2. `npm run deploy` — **ต้อง build ใหม่** เพราะ `robots.txt` และแท็ก `<meta name="robots">`
   ถูกสร้างตอน build ไม่ใช่ตอนรัน สคริปต์ปรับ `SITE_NOINDEX` และ `NEXT_PUBLIC_SITE_URL`
   ใน `app.env` ให้ตรงกันเอง
3. ถ้าย้ายไปโดเมนใหม่ใน subscription เดิม ตั้ง `REMOTE_APP` เป็นชื่อโฟลเดอร์ของโดเมนนั้นด้วย
4. ส่ง sitemap เข้า Google Search Console
